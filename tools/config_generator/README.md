# Therefore Config Generator (Category MVP)

This module generates **delta XML** for new categories from a **natural language description** (or YAML/JSON spec).

## Current Scope (MVP)
- Category creation
- Folder creation (if needed)
- Basic field types: `text`, `number`, `decimal`, `date`
- Keyword dictionaries: **existing** and **new** (single-select)
- Auto layout if no sizing/position is specified

Not yet supported: workflows, role assignments, tables, tabs, counters, checkboxes, date/time, etc.

## Usage

```
python3 /Volumes/DataSSD/source/therefore-mcp/tools/config_generator/generate.py \
  --baseline /path/to/TheConfiguration.xml \
  --description /path/to/description.txt \
  --output /path/to/delta.xml
```

The description can be either:
- **Natural language** (recommended)
- **YAML/JSON spec** (if `PyYAML` is installed, YAML is supported; JSON always works)

### Natural language example
```
Create a category "My New Category" in folder "Testing for Codex".
Fields:
- text field "My text field 50" length 50
- number field "my number field" length 10
- decimal field "my decimal field" length 10 scale 4
- date field "Contract End"
- keyword field "Codex Test Dictionary" with new dictionary "Codex Test Dictionary" keywords: Value 1, Value 2, Value 3
- keyword field "Yes No Keyword Field - already existed" using existing dictionary "Yes No"
```

### YAML spec example
See `tools/config_generator/specs/category_spec_example.yaml`.

## Output
The tool produces a **delta XML** with:
- `<Version>` and `<NewImportExport>` copied from baseline
- `<Folders>` if a new folder is needed
- `<Categories>` with the new category and fields
- `<KeywordDictionaries>` if new dictionaries are requested

## Notes
- New objects use **negative IDs** (local to the import file).
- For new dictionaries, table names (`TheKeywordsNN`) are generated by finding the next available suffix from baseline.
- Existing dictionaries are resolved by name from baseline.

## Folder conflicts
If a folder name already exists in the baseline export and the description requests a **new** folder, the generator defaults to **use existing** unless you specify a policy:

- Natural language: add **"use existing folder"** or **"create unique folder name"**
- YAML/JSON spec: `folder_conflict_policy: use-existing|unique|error`
- CLI: `--folder-on-exists use-existing|unique|error` (default: `use-existing`)

You can also enable prompting (only when API checks are enabled):
- CLI: `--api-check --interactive` (prompts to use existing, create unique, or abort)

## Dictionary lookups via API
If `--api-check` is enabled, the generator will attempt to resolve **existing keyword dictionaries** by name via WebAPI:
1. `GetObjectsList` with `Type=KeyDict` to find the dictionary by name
2. `GetDictionaryInfo` to retrieve `SingleTypeNo`

This allows “existing dictionary” fields to work even if the baseline export does not include that dictionary.

If `THEREFORE_ENV_PATH` is set and points to a valid `.env`, the generator will automatically try API checks
even without `--api-check`.
